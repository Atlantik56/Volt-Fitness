# Аудит информационной безопасности VOLT

Дата: 22 июля 2026. Объём: исходный код приложения, API, авторизация, загрузка файлов, зависимости и схема будущего VPS-развёртывания.

## Результат

Критических уязвимостей в собственном коде после доработки не обнаружено. Персональные API и фотографии требуют действующую сессию. В проекте больше нет ключей или runtime-зависимости от ChatGPT, Cloudflare D1/R2, Google Fonts, Unsplash и внешних CDN.

## Исправлено в ходе аудита

| Риск | Решение |
|---|---|
| Данные и фото были доступны без аутентификации | Все соответствующие API закрыты `requireAuth()` |
| Внешняя платформа хранила БД и фото | SQLite и каталог uploads находятся в локальном `DATA_DIR` |
| Подмена межсайтовых POST-запросов | `SameSite=Strict` и проверка `Origin` |
| Кража токена клиентским JavaScript | `HttpOnly`, `Secure` в production, в БД хранится только SHA-256 токена |
| Подбор пароля | scrypt с солью, минимум 12 символов, блокировка на 15 минут после 5 ошибок |
| Маскировка вредоносного файла под фото | лимит 8 МБ, whitelist MIME, проверка magic bytes, случайное имя, запрет исполнения |
| Clickjacking, MIME sniffing, лишние browser capabilities | CSP, `frame-ancestors 'none'`, `nosniff`, Permissions-Policy, Referrer-Policy |
| Утечка личного ответа через cache | `Cache-Control: no-store` для fitness API и private cache для фото |

## Остаточные риски и обязательные меры VPS

1. Публиковать только через HTTPS (Caddy/Nginx) и не открывать порт 3000 наружу. Compose уже привязывает его к `127.0.0.1`.
2. Ограничение попыток входа рассчитано на один экземпляр приложения. При горизонтальном масштабировании перенести rate-limit в общий Redis/БД.
3. Регулярно резервировать volume `volt-data`; потеря volume означает потерю профиля, пароля и фотографий.
4. Включить firewall, unattended security updates, журналирование входов на reverse proxy и ограничение размера тела запроса 10 МБ.
5. `npm audit` сообщает о вложенном `sharp@0.34.5` в Next.js (GHSA-f88m-g3jw-g9cj). Приложение не использует Next Image Optimizer и самостоятельно не передаёт загруженные фото в Sharp, поэтому известный путь атаки сейчас недостижим. Обновить Next.js, как только он поставит `sharp >=0.35.0`; не применять предложенный npm downgrade до Next 14/9.
6. PWA-кэш намеренно не хранит HTML, API или пользовательские фотографии. Это снижает офлайн-возможности, но не оставляет персональные данные в общем Cache Storage.
