# Редизайн режима проведения тренировки (Workout Session)

Статус: проект / готов к реализации
Область: только UI и логика прохождения тренировки внутри `WorkoutModal` (`app/page.tsx`).
Не затрагивается: тренировочные планы (`personal-data.ts`), SQLite/`lib/db.ts`, `/api/fitness`, AI Coach (`progressionDecision`, `exerciseReplacement`), питание, аналитика, расчёт прогресса.

> Примечание: файлы `AGENTS.md`, `CLAUDE.md`, `docs/PRODUCT.md`, `docs/ARCHITECTURE.md`, `docs/CURRENT_TASK.md`, `docs/DECISIONS.md` в репозитории не найдены — документ подготовлен на основе анализа исходного кода (`app/page.tsx`, `app/globals.css`, `app/personal-data.ts`, `app/exercise-*.ts`).

## 1. Анализ текущего режима тренировки

Текущая реализация — `WorkoutModal` (app/page.tsx:221-271) + `WorkoutExerciseCard` (app/page.tsx:255-271):

- Открывается как модалка (`modal-backdrop.focus-mode`) поверх страницы — уже полноэкранная на десктопе (`height:100dvh`), это шаг в верном направлении.
- Состояния: `stage` (`warmup` → `rounds`), `round` (индекс текущего круга), `summary` (флаг завершения).
- Внутри стадии `rounds` для **текущего круга разом рендерятся все упражнения** в виде вертикального списка карточек (`workout-checks.visual`) — чекбокс, фото, описание, поле "фактически", поле веса, селект сложности — всё видно одновременно.
- Переключение между кругами — через `round-tabs`, но это те же списки, просто с других данными.
- Отдых **между кругами** — отдельный полноэкранный экран (`rest-screen`) с таймером, счётом вверх (не вниз) и одной кнопкой "Я готов".
- Отдых **между упражнениями** — не экран, а плавающая кнопка-таймер (`exercise-rest-button`, портал в `document.body`), которую пользователь включает/выключает вручную поверх всё того же списка.
- Черновик тренировки сохраняется в `localStorage` (`volt-active-workout`, версия `workoutDraftVersion=3`) и восстанавливается при повторном открытии — это уже даёт устойчивость к случайному закрытию вкладки/сворачиванию телефона.
- Экран завершения (`summary`) — калории/пульс/дистанция вводятся вручную, плюс блок AI-рекомендаций по прогрессии (`progressionDecision`) на каждое упражнение.
- Замена упражнения при боли ("Больно / неудобно") — раскрывающаяся панель прямо внутри карточки упражнения.

## 2. Проблемы UX

1. **Нет фокуса на одном упражнении.** Пользователь во время сета/подхода видит весь круг сразу — это ровно то, что просили убрать. Много визуального шума в момент, когда нужно просто "сделать и отметить".
2. **Отдых между упражнениями необязателен и неочевиден** — это ручной тумблер-кнопка, а не часть потока. Легко забыть включить/выключить, легко пропустить отдых незаметно для себя.
3. **Разное число кликов для похожих действий** — чекбокс + числовое поле + (иногда) вес + селект сложности заполняются одновременно, вперемешку с обычным skim по списку.
4. **Нет единого "одно действие на экран".** На экране круга одновременно активны N чекбоксов, N полей ввода, N кнопок "Больно/неудобно" — нет иерархии внимания.
5. **Экран отдыха между кругами не показывает следующее упражнение** — только "круг N завершён", хотя после отдыха начинается конкретное упражнение (первое в следующем круге).
6. **Прокрутка вместо навигации.** Чтобы дойти до последнего упражнения круга, нужно скроллить длинный список — на телефоне это медленнее и требует двух рук.
7. **Мобильная и десктопная версия визуально одна и та же** (просто уже колонка на мобильном) — нет использования доп. пространства на ноутбуке для разумной двухколоночной раскладки, при этом нет и настоящего "одно упражнение на экран" ни на одном устройстве.

## 3. Поддерживаемые сценарии

- Тренировка с разминкой и без.
- Тренировка с несколькими кругами и с одним кругом.
- Упражнение с отдыхом после него и без отдыха (последнее упражнение круга/тренировки — отдыха не будет).
- Силовое упражнение (нужны вес, повторы, сложность) и активность без силовых полей (заминка/растяжка без веса).
- Кардио/плавание/велосипед — отдельный набор метрик на экране завершения (пульс, дистанция, скорость) — сохраняется как есть.
- Замена упражнения по боли/неудобству — доступна прямо на экране упражнения.
- Просмотр техники (видео) — доступен прямо на экране упражнения.
- Прерывание тренировки и возобновление позже (закрыл телефон/сел заряжать) — черновик в localStorage.
- Досрочный выход с явным сбросом прогресса тренировки.
- Прохождение одной рукой на телефоне — все основные действия достижимы большим пальцем снизу экрана.

## 4. Пользовательский сценарий (от старта до завершения)

1. Пользователь на главном экране нажимает "Начать тренировку" → открывается `WorkoutSession` на весь экран (тот же компонент на всех устройствах).
2. Если есть разминка — первый экран `ExerciseCard` показывает первое упражнение разминки. Прогресс вверху: "Разминка · 1 из 3".
3. Отмечает выполненным ("Готово") → если нужен ввод результата (силовое упражнение), сразу под кнопкой разворачивается компактная форма (вес/повторы/RPE) → "Сохранить и продолжить".
4. Автоматически открывается следующий экран:
   - если после этого упражнения предусмотрен отдых → `RestCard` с таймером обратного отсчёта и названием следующего упражнения;
   - если отдых не нужен (или это последнее упражнение) → сразу следующий `ExerciseCard`.
5. На `RestCard` пользователь может "Пропустить отдых" в любой момент; по истечении таймера — автопереход на следующий экран.
6. Цикл (упражнение → возможно отдых) повторяется для всех упражнений во всех кругах. Переход между кругами не требует отдельного экрана-развилки — это то же самое "следующее упражнение", просто первое упражнение следующего круга (с отдыхом перед ним, если задан).
7. После последнего упражнения — `FinishCard`: поздравление, длительность, число упражнений/подходов, калории (если есть), кнопка "Готово" → возврат на главный экран, данные сохраняются как раньше через `/api/fitness`.
8. В любой момент доступна кнопка закрытия (иконка ×) в углу — с подтверждением сброса прогресса (используется нативный `confirm`, как уже сделано для похожих действий в проекте, например `WorkoutHistory`/`Photo`).

## 5. Предлагаемая архитектура компонентов

```
WorkoutOverview (существующий — карточка плана на главном экране, без изменений)
        │  onClick "Начать тренировку"
        ▼
WorkoutSession                     — контроллер: state machine + layout-обёртка
 ├── useWorkoutSession()           — хук: строит линейную последовательность шагов
 │                                   [{type:"exercise", ...}, {type:"rest", ...}, ...]
 │                                   из warmup+rounds×exercises, держит текущий индекс,
 │                                   таймеры, черновик в localStorage, сбор details
 ├── SessionHeader                 — прогресс (X из N), кнопка закрытия, общий таймер
 ├── ExerciseCard                  — один текущий степ-упражнение
 │    └── ResultForm               — форма вес/повторы/RPE после "Готово" (условно)
 ├── RestCard                      — экран отдыха (между упражнениями И между кругами —
 │                                   один и тот же компонент, разн. пропсы)
 └── FinishCard                    — экран завершения + метрики + AI-прогрессия
```

Ключевая идея: **последовательность шагов строится один раз** в `useWorkoutSession` как плоский массив `Step[]` (`exercise | rest`), а не как вложенные `stage/round`. Текущий шаг — просто `steps[cursor]`. Это убирает дублирование условий "если это последнее упражнение круга" / "если это последний круг" — переход всегда `cursor+1`, автопереход после отдыха — тоже `cursor+1`.

```ts
type Step =
  | { type: "exercise"; key: string; exercise: ExerciseRef; needsResult: boolean }
  | { type: "rest"; key: string; seconds: number; nextExerciseName: string };
```

`WorkoutSession` не знает про "круги" и "разминку" как про разные UI-режимы — это просто откуда взялись элементы `steps`. Разминка и круги отличаются только тем, что у элементов разминки `needsResult=false` (или упрощённая форма), а у силовых кругов — `needsResult=true`.

## 6. Что переиспользуется

- `exerciseVideoId` / `<ExerciseVideo>` — без изменений, встраивается в `ExerciseCard`.
- `exerciseReplacement` + панель "Больно / неудобно" — логика без изменений, переносится в `ExerciseCard` как раскрывающийся блок.
- `progressionDecision` — используется в `FinishCard`, как сейчас в `summary`.
- Формат вызова `/api/fitness` (`action:"workout"`) — не меняется, все поля (`details`, `effort`, `painAfter`, метрики) собираются так же.
- `localStorage`-черновик (`volt-active-workout`) — сохраняется, но формат обновляется под новый плоский `cursor`-based state (бампнуть `workoutDraftVersion` до `4`, старые черновики отбрасываются — это разовая, не пользовательская, потеря 1 незавершённой тренировки максимум).
- `readWorkoutDraft`, `localIso`, `clock`-форматтер — без изменений.
- Экран завершения: структура summary-grid, progress-decisions, result-fields (пульс/калории/дистанция) — переносится в `FinishCard` почти 1:1.
- Кнопка/попап замены упражнения, бейдж "БЕЗОПАСНАЯ ЗАМЕНА" — переносится как есть.
- CSS-переменные и цветовая схема (`--lime`, `--line` и т.д.) — без изменений.

## 7. Что заменяется

- `WorkoutModal` как единый компонент с внутренним `stage`/`round` state → заменяется на `WorkoutSession` + `useWorkoutSession`.
- `WorkoutExerciseCard`, рендерящий **список** упражнений → заменяется на `ExerciseCard`, рендерящий **одно** упражнение (переиспользует те же под-блоки: фото, описание, поля ввода, видео, замену).
- `workout-checks.visual` (сетка карточек) и `round-tabs` — убираются из UI прохождения тренировки (сама механика кругов остаётся в данных, просто не показывается как переключатель).
- Плавающая кнопка `exercise-rest-button` (портал в body) — заменяется полноценным экраном `RestCard`, который включается автоматически.
- `rest-screen` (отдых только между кругами) — обобщается до `RestCard`, работающего и между упражнениями, и между кругами (что для пользователя один и тот же смысл — "жди перед следующим упражнением").

## 8. Адаптивность

Один компонент `WorkoutSession`, один и тот же React-стейт и переходы на всех устройствах. Разница — только CSS (grid/flex-раскладка), без ветвления логики и без двух разных деревьев компонентов.

- **Телефон (≤ 760px, как в текущих брейкпоинтах проекта):** `ExerciseCard` занимает почти весь экран, одна колонка, фото/видео сверху, кнопка "Готово" зафиксирована снизу (`position:sticky; bottom`) — достижима большим пальцем без скролла в большинстве случаев.
- **Планшет (760–1024px):** та же одноколоночная структура, но крупнее шрифты/отступы/фото — использует пространство, не добавляя новых блоков.
- **Ноутбук (> 1024px):** двухколоночная раскладка внутри `ExerciseCard` через CSS grid — левая колонка: фото/видео; правая: название, техника, рекомендации, форма ввода результата, кнопка "Готово". Небольшая полоса прогресса сверху (текст "Упражнение X из N" + тонкий прогресс-бар) — не список, просто индикатор. `RestCard` и `FinishCard` остаются по центру экрана в обеих раскладках (там нет двух логических колонок контента).
- Брейкпоинты берутся из уже существующих в проекте (`max-width:760px`, использованный `focus-mode` подход с `calc((100vw - 820px)/2)` для центрирования на широких экранах) — не вводится новая система адаптивности.

## 9. Риски

| Риск | Митигация |
|---|---|
| Черновик `localStorage` в старом формате (`stage/round/checks`) не совместим с новым `cursor`-based состоянием | Бампнуть `workoutDraftVersion`; `readWorkoutDraft` уже проверяет версию и отбрасывает несовпадающую — старый черновик просто не восстановится (тренировка в процессе на момент деплоя потеряется один раз, это принято как приемлемый разовый компромисс). |
| Пользователь привык переключать `round-tabs` вручную (посмотреть вперёд/назад) — в линейном режиме "шаг назад" не предусмотрен ТЗ | Явно не реализуем шаг назад в первой версии (ТЗ говорит "минимизировать количество кликов", не про навигацию назад); если понадобится — на `ExerciseCard` можно добавить необязательную кнопку "Назад" без изменения архитектуры `Step[]`. |
| Разница в объёме кода — `ExerciseCard` должен обслуживать и "разминочные" элементы (без веса/сложности) и "силовые" (с весом/сложностью) через один компонент | Управляется пропом `needsResult`/`showLoad`, как уже сделано в `WorkoutExerciseCard` (`showLoad` проп уже существует) — переносится без изменений логики. |
| Автопереход после отдыха может застать пользователя врасплох (например, отошёл от телефона) | Оставляем ручное "Пропустить отдых" как основной путь на практике; автопереход — это то, что ослабляет необходимость лишнего клика, а не единственный путь. Плюс короткая пауза перед автопереходом (визуальное подтверждение "0:00") — не мгновенный skip. |
| Регрессия в `/api/fitness` из-за изменения структуры `details` | Финальный payload в `finish()` не меняется по форме — тот же `details.map(...)`, просто собирается из линейного массива шагов вместо вложенных циклов `rounds × exercises`. Формат объекта, который уходит на сервер, идентичен текущему. |
| Тесты/типы не покрывают текущий `WorkoutModal` (нет `*.test.*` файлов в репозитории на момент анализа) | Ручная проверка по чеклисту в разделе "Проверка" ниже — обязательна перед мёржем, раз автотестов нет. |

## Расширяемость (без переделки архитектуры)

Заложено самой структурой `Step[]` + единой точкой перехода `advance()`:
- **Голосовые подсказки / вибрация** — побочный эффект в момент входа в шаг (`useEffect` на смену `cursor`), не меняет структуру.
- **Автозапуск отдыха / автозапуск следующего упражнения** — уже реализовано как основной путь (`RestCard` автопереходит по таймеру); "авто-старт упражнения без промежуточного тапа" — просто убрать необходимость нажатия и сразу монтировать `ExerciseCard` с активным заданием.
- **Дополнительные режимы тренировки** (например, HIIT с таймером на упражнение вместо счётчика повторов) — новый вариант `Step` (`{type:"exercise", mode:"timed", seconds}`) и соответствующий вариант рендера в `ExerciseCard`, без изменения `WorkoutSession`/`useWorkoutSession`.
