# VOLT AI Hub — handoff для Claude

Актуально на 26 июля 2026 года. Этот документ фиксирует реализованную
интеграцию Anthropic + MWS GPT, чтобы следующая сессия могла продолжить работу
без повторного исследования проекта.

## Что реализовано

В чате VOLT Coach пользователь может выбрать один из четырёх режимов:

| Режим | Значение API | Поведение |
|---|---|---|
| Авто | `auto` | Запрос идёт в Anthropic. MWS используется только как резерв при серверной ошибке Anthropic (`5xx`). |
| Anthropic | `anthropic` | Запрос строго в Anthropic, без переключения на MWS. |
| MWS GPT | `mws` | Запрос строго в MWS GPT. |
| Консилиум | `consensus` | Anthropic создаёт черновик, затем MWS получает компактный контекст и черновик, проверяет его и выдаёт финальный ответ. |

Консилиум делает ровно по одному обращению к каждой модели. Это сознательное
ограничение стоимости: нет циклических дебатов и повторных запросов.

Дневная квота чата общая для всех режимов и по-прежнему проверяется сервером.
Неуспешное обращение освобождает зарезервированную квоту.

## Архитектура и изменённые файлы

- `lib/ai-coach.ts` — адаптеры Anthropic и MWS, нормализация ошибок.
- `lib/ai-hub.ts` — маршрутизация между провайдерами и сценарий консилиума.
- `app/api/coach-chat/route.ts` — принимает `provider`, применяет квоту,
  формирует контекст и сохраняет ответ.
- `app/api/settings/route.ts` — серверная настройка MWS.
- `app/coach-chat-panel.tsx` — выбор модели, настройка MWS и отображение
  фактически ответившего провайдера.
- `.env.example` — документированные имена переменных без значений секретов.
- `tests/ai-coach.test.ts` — тесты адаптеров, маршрутизации, fallback и
  консилиума.
- `docs/VOLT_ROADMAP.md` — продуктовый статус AI Hub.

Основной принцип проекта не изменился: тренировки, нагрузки и прогресс считает
детерминированный код VOLT, а LLM объясняет результат и ведёт диалог. Модели не
должны самостоятельно менять фактические данные пользователя в базе.

## MWS GPT

Текущая конфигурация деплоймента:

- проект: `project-avatar-aang5615`;
- имя деплоймента в консоли: `Volt-Ai`;
- API model id: `qwen3-6-35b-a3b`;
- endpoint:
  `https://gpt.mwsapis.ru/projects/{project}/openai/v1/chat/completions`;
- формат API совместим с OpenAI Chat Completions;
- сервисному аккаунту нужна роль `gpt.inferencer`.

MWS-запрос отправляется с заголовком `Authorization: Bearer <API_KEY>`.

### Где хранится конфигурация

Пользователь вводит ключ, проект и model id через шестерёнку в чате Coach.
Настройки сохраняются только на сервере в SQLite:

- `mws_api_key`;
- `mws_project`;
- `mws_model`.

`GET /api/settings` никогда не возвращает ключ — только флаг `mwsKeySet` и
несекретные project/model. В браузер и Git значение ключа попадать не должно.

Поддерживаются серверные fallback-переменные:

```dotenv
MWS_API_KEY=
MWS_PROJECT=project-avatar-aang5615
MWS_MODEL=qwen3-6-35b-a3b
```

SQLite не шифруется на уровне приложения, поэтому ключ также присутствует в
серверных резервных копиях базы. Не печатать его в логах и не добавлять в
диагностические ответы API.

### Незавершённое: авторизация MWS

На последней проверке ручной режим MWS возвращал `401`. Пользователь сообщил,
что создаёт новый API-ключ. Поэтому подключение MWS пока нельзя считать
подтверждённым, даже если UI показывает, что ключ сохранён.

После получения нового ключа:

1. В Coach открыть настройки MWS через шестерёнку.
2. Вставить новый ключ, проверить project и model id из раздела выше.
3. Сохранить; старый ключ отозвать в консоли MWS.
4. Выбрать «MWS GPT» и отправить короткое сообщение.
5. Убедиться, что ответ успешен и интерфейс указывает MWS как провайдера.
6. Затем проверить «Консилиум».

Если снова возникает `401`, проверить именно:

- ключ выпущен для нужного сервисного аккаунта;
- у аккаунта есть роль `gpt.inferencer`;
- ключ не отозван и вставлен полностью, без префикса `Bearer`;
- проект в VOLT совпадает с проектом деплоймента;
- биллинг-аккаунт MWS активирован.

Не обходить проблему переключением Auto: Auto может успешно ответить через
Anthropic и тем самым скрыть неработающий MWS.

## Стоимость и дальнейшая работа

Пользователь ориентируется на расходы до 7 долларов в месяц. Точной
автоматической информации об остатке долларов или лимитах провайдеров сейчас
нет: API чата возвращает локальную дневную квоту VOLT, а не внешний баланс.
Не показывать выдуманный баланс. Для реального отображения затрат потребуется
отдельный серверный учёт токенов и тарифов либо официальный billing API
каждого провайдера.

При дальнейших изменениях сохранить следующие свойства:

- Anthropic остаётся основной моделью;
- явный выбор провайдера должен соблюдаться строго;
- fallback в Auto — только на серверные ошибки, но не на ошибки конфигурации;
- ключи не возвращаются клиенту;
- консилиум не должен незаметно превращаться в многократный дорогой диалог;
- изменение тренировочного плана должно проходить через валидируемые правила
  домена, а не через свободную запись LLM в SQLite.
