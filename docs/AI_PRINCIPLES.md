# Принципы AI в VOLT

Статус: обязательные ограничения для Sprint AI-1…AI-6 и последующих
AI-функций. Изменять их можно только отдельным архитектурным решением, а не
попутно внутри спринта.

## Продуктовая роль

VOLT — поддерживающий тренер по привычкам и фитнесу, а не психолог, врач,
надзиратель или замена человеческому общению. Он помогает увидеть факты,
закономерности и один реалистичный следующий шаг.

- Честные данные ценнее красивой статистики.
- Пользователь сравнивается только со своей прошлой версией.
- Один тяжёлый день не называется провалом или срывом.
- Алкоголь — один из факторов вечера, а не центральная оценка человека.
- При недостатке данных VOLT прямо говорит об этом.
- Медицинские и психологические диагнозы запрещены.
- Корреляция не описывается как доказанная причина.

Запрещённые формулировки: «ты сорвался», «ты провалил цель», «плохой день»,
«нужно было лучше стараться». Предпочтительны нейтральные формулировки:
«сегодня получилось не так, как планировалось», «спасибо за честную запись»,
«данных пока мало», «завтра можно попробовать один небольшой шаг».

## Код считает, LLM объясняет

Детерминированный код VOLT:

- нормализует исходные данные;
- считает агрегаты, тренды, сравнения и confidence;
- применяет пороги достаточности данных;
- выбирает допустимый инсайт и рекомендацию;
- решает, показывать ли инсайт повторно.

LLM:

- получает компактные агрегированные факты и готовые выводы;
- превращает их в естественный поддерживающий текст;
- не пересчитывает статистику;
- не получает полную сырую историю без отдельной обоснованной функции;
- не меняет тренировочный план и фактические данные напрямую.

Lite Coach обязан работать без внешнего API. MWS GPT может использоваться для
коротких ежедневных формулировок, Claude — для явно запрошенных глубоких
разборов. Открытие страницы само по себе не должно вызывать платный запрос.

## Приватность и стоимость

- Сначала локальная SQLite и локальные вычисления.
- В облако отправляются только минимально необходимые агрегаты.
- Заметки и дневниковый текст не отправляются автоматически целиком.
- Секреты остаются на сервере и не возвращаются клиенту.
- Для каждого нового LLM-вызова должны быть определены триггер, лимит,
  fallback и ожидаемый размер контекста.
- Нельзя вводить скрытые фоновые вызовы моделей.

## Эволюция вместо переписывания

- Переиспользовать `lib/ai-context.ts`, `lib/coach.ts`,
  `lib/coach-insights.ts`, `lib/evening.ts`, `lib/mood.ts` и существующие
  доменные сервисы.
- Не создавать новые «Engine» только ради названия.
- Не объединять домены с разными инвариантами безопасности в универсальную
  абстракцию.
- Не менять стек, БД целиком, API-контракты и UI вне scope спринта.
- Любая миграция БД должна быть аддитивной, обратимо развёртываемой и
  протестированной на существующих данных.

## Достоверность данных

- `null`/отсутствие данных не равно нулю.
- Хранятся исходные значения, а производные можно пересчитать.
- Автозаполненные, ручные и импортированные данные в будущем должны различаться.
- Любой инсайт содержит стабильный id, использованные сигналы, период,
  evidence count и уровень уверенности.
- Низкая уверенность не маскируется уверенным текстом.

## UX

- Ввод можно пропустить и позже исправить.
- Существующая запись не затирается молча.
- Формы запрашивают только неизвестные данные.
- Красные штрафы, отрицательные очки и серии «0 дней без пива» запрещены.
- На экране показывается не более одного основного следующего шага.

## Проверка каждого спринта

Минимум: целевые unit-тесты, полный `npm test`, `npm run typecheck`,
`npm run lint`, `npm run build`. UI-спринты дополнительно проверяются вручную
на desktop и ширинах 360–412 px. Документационные изменения должны сохранять
рабочие относительные ссылки.
