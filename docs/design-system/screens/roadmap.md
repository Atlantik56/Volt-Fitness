# Roadmap / «Дорожная карта»

## Назначение экрана

«Дорожная карта» — визуальная карта всего тренировочного пути: где пользователь
находится сейчас, какие этапы уже прошёл и что ждёт дальше. Это не Analytics и
не ещё один экран оценки выполнения тренировок.

Экран отвечает на вопрос «где я сейчас в 36-недельной программе?» и сохраняет
метафору:

**путь → этапы → текущая позиция → следующая цель.**

## Верхний summary

Верхний summary показывает только календарное положение внутри программы:

- дату старта программы;
- текущую неделю `N из 36`;
- календарный прогресс по 36-недельной программе.

Значения берутся из существующих данных программы. Даты и числа в mockup —
пример состояния, а не значения для hardcode. Календарный прогресс определяется
положением во времени относительно даты старта, а не количеством выполненных
тренировок.

## Фазы программы

Текущая фаза определяется календарной неделей программы относительно даты её
старта:

1. **Адаптация — недели 1–12.** Формируем привычку, возвращаем базовую
   выносливость и укрепляем тело.
2. **Развитие — недели 13–24.** Постепенно увеличиваем нагрузку, развиваем силу
   и выносливость.
3. **Мастерство — недели 25–36.** Переходим к более высокой интенсивности и
   закрепляем достигнутую форму.

Текущая фаза и текущая позиция должны быть визуально доминирующими; следующие
этапы остаются видимыми, но спокойнее. Roadmap не оценивает качество или процент
выполнения тренировок и не вводит новый показатель эффективности. Выполнение
конкретных тренировок остаётся ответственностью Plan и Analytics.

## Визуальный контракт

[roadmap-approved.png](../assets/approved-screens/roadmap-approved.png) —
обязательный утверждённый reference для композиции «Дорожной карты» на desktop
и mobile.

Home остаётся главной
[Reference Implementation](../08-reference-implementation.md) для материала,
общего background, типографики, spacing, иерархии, VOLT Glass и визуальной
плотности. Roadmap наследует этот язык, а утверждённый mockup задаёт только
специфичную для экрана композицию пути, фаз и текущей позиции.

Mountain imagery в mockup — композиционный reference метафоры пути к цели. Это
не разрешение генерировать, перерисовывать или подменять assets. Если для
реализации нужны отдельные изображения, которых нет среди утверждённых файлов,
необходимо остановиться и запросить исходники или отдельное решение.

На mobile сохраняются та же вертикальная структура, порядок фаз, текущая
позиция и продуктовый смысл; экран не превращается в другую композицию.

Завершающая мысль экрана:

**«Последовательность создаёт результат».**

## Границы реализации

- Сохранять существующие данные, маршруты, состояния и поведение приложения.
- Не смешивать Roadmap с Plan или Analytics.
- Не добавлять новые метрики, оценки дисциплины или эффективности.
- Не считать отсутствие отдельного asset разрешением на визуальную
  импровизацию.
