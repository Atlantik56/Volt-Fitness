# Sprint AI-3 — адаптивный вечерний чек-ин

Статус: продуктовое и техническое задание. Начинать после AI-2.

## Цель

Кнопка «Завершить день» в «Вечернем прогрессе» запускает короткий мастер на
30–60 секунд. VOLT предварительно подставляет известные данные, спрашивает
только недостающее, затем показывает сводку и сохраняет подтверждённые исходные
значения.

Чек-ин завершает день, а не выставляет оценку человеку.

## Ожидаемые точки изменения

- `app/evening-progress.tsx`
- новые презентационные компоненты чек-ина в `app/`
- `app/page.tsx` только для подключения потока/данных
- `app/api/fitness/route.ts` и доменный сервис, если запись нужно вынести
- `lib/db.ts` для аддитивной миграции недостающих полей
- `lib/evening.ts` для нормализации и локальной сводки
- `app/globals.css` или профильный CSS
- новые unit-тесты модели чек-ина и API/service tests

Сначала проверить реальные модели и не создавать вторую сущность для данных,
которые уже принадлежат `daily_activity`, `mood_logs` или `wellness_logs`.

## Пользовательский поток

1. На странице показана кнопка «Завершить день» или «Изменить вечерний чек-ин».
2. При открытии загружаются данные текущей даты.
3. Известные подтверждённые значения отображаются заполненными.
4. Полностью известный блок можно пропустить; пользователь может раскрыть его
   для корректировки.
5. Вопросы показываются небольшими шагами с индикатором прогресса.
6. Перед записью показывается итоговая сводка.
7. Сохранение выполняется только после подтверждения.
8. Повторное открытие редактирует ту же запись даты, не создаёт дубликат.
9. После успеха: «Спасибо за честную запись».

## Блоки

### Настроение

- один выбор из существующей шкалы настроения;
- необязательная короткая заметка;
- существующая `mood_logs` за дату подставляется автоматически.

### Сон

Хранить исходные значения:

- дата/время начала сна;
- дата/время окончания сна;
- рассчитанная длительность в минутах;
- необязательная субъективная оценка качества.

Требования:

- сон может пересекать полночь;
- длительность рассчитывается кодом, не вводится независимо;
- пользователь видит начало, окончание и формат `7 ч 40 мин`;
- существующий `sleepHours` сохраняется совместимо или вычисляется из минут;
- конфликт импортированного и ручного значения нельзя молча разрешать
  перезаписью: показать источник и запросить подтверждение.

### Вода

- значение в литрах;
- быстрые варианты `0,5 / 1 / 1,5 / 2 / 2,5 / 3+`;
- точная корректировка с шагом 0,25 л;
- допустимый диапазон валидируется сервером;
- не использовать оценку «достаточно/мало» вместо числа.

### Алкоголь

Сначала выбор «не пил / пил». При «не пил» дополнительные поля скрыты и
сохраняется явный ноль только после подтверждения.

При «пил»:

- тип напитка;
- количество банок или порций;
- объём одной банки/порции в мл;
- время первого напитка;
- опционально «меньше / как обычно / больше» только как субъективная метка.

Для пива быстрый ввод должен позволять, например, `3 × 450 мл, начало 21:35`.
Последний объём можно предложить как default, но пользователь подтверждает его.
Количество банок без объёма недостаточно для аналитики. Не переводить разные
напитки в «банки пива» и не рассчитывать медицинские единицы алкоголя в этом
спринте.

### Питание и ужин

- использовать существующие `food_logs`, если приём пищи уже записан;
- спросить факт ужина или субъективную краткую оценку только при нехватке;
- не дублировать дневник КБЖУ;
- варианты не должны использовать стыдящие формулировки.

### Самочувствие и фактор дня

- существующие энергия, боль, область боли и заметка подставляются;
- главный фактор дня: работа, стресс, семья, отдых, тренировка, болезнь,
  поездка, другое;
- фактор и заметка необязательны;
- свободный текст хранится как данные пользователя, не инструкция AI.

## Адаптивность

Функция построения шагов должна быть чистой и детерминированной:

- записанная тренировка не спрашивается повторно;
- известный сон/вода/настроение отображаются как подтверждаемые;
- алкогольный detail-step существует только при «пил»;
- скрытие шага не удаляет ранее сохранённое значение без явного подтверждения;
- пользователь всегда может открыть «Проверить все данные»;
- отсутствие интеграции с часами не создаёт фиктивный источник.

## Сводка дня

Перед сохранением показать только факты:

```text
Тренировка: выполнена
Сон: 00:20–07:10, 6 ч 50 мин
Вода: 1,75 л
Пиво: 3 × 450 мл, первый напиток в 21:35
Настроение: хорошее
Ужин: отмечен
```

Каждая строка редактируется. Не показывать балл дня `7/10`, штрафы, красную
оценку или серию дней без алкоголя.

## Модель сохранения

- Сохранять сырые значения и производные длительности отдельно только когда
  это нужно для совместимости/запросов.
- Одна дата — одна соответствующая дневная запись в каждой существующей
  таблице.
- Мульти-табличное сохранение должно быть атомарным либо иметь безопасный
  повтор без дублей.
- Сервер повторно валидирует числа, время, enum и длину текста.
- API возвращает нормализованную сохранённую сводку.
- Локальная аналитика пересчитывается после успешного ответа; LLM не вызывается.

## Миграция

До миграции составить mapping существующих полей. Предпочтительное расширение
`daily_activity`:

- `sleepStart`, `sleepEnd`, `sleepMinutes`, `sleepQuality`;
- существующий `waterLiters`;
- существующие `beers`, `firstDrinkTime`;
- дополнительные `alcoholType`, `alcoholUnits`, `alcoholUnitVolumeMl`;
- фактор дня — только если ему нет естественного существующего места.

Названия подтвердить по conventions проекта. Миграция аддитивная; legacy
`sleepHours`/`beers` читаются совместимо. Не выполнять разрушительный backfill
по догадке.

## Не входит

- Автоматическая синхронизация с часами.
- Медицинский пересчёт алкоголя и диагноз зависимости.
- LLM-анализ введённого текста.
- Memory и новые кросс-доменные инсайты.
- Перенос всех форм приложения в единый form framework.

## Тесты

- Сон в пределах дня и через полночь; неверный обратный интервал.
- Длительность округляется/форматируется корректно.
- Вода: границы, шаг, десятичная запятая/точка на UI при необходимости.
- «Не пил», одна банка, несколько банок, разные объёмы, отсутствие времени.
- Conditional-step алкоголя и восстановление сохранённого ответа.
- Автозаполнение не затирает существующее.
- Повторное сохранение идемпотентно.
- Частичный API-сбой не оставляет дубли/полусохранённую запись.
- Сводка совпадает с нормализованным payload сервера.
- Существующая страница «Вечерний прогресс» продолжает работать.
- Ручная QA desktop и 360/390/412 px, клавиатура и focus order.

## Критерии готовности

- Типовой незаполненный чек-ин занимает не более 6 содержательных шагов.
- Известные значения не требуют повторного ввода.
- Сон, вода и алкоголь сохраняются в числах/времени, а не только оценками.
- Итог можно исправить до сохранения.
- Нет LLM-запроса и расхода токенов.
- Все автоматические проверки и ручная адаптивная QA проходят.
- Фактическая схема и UX записаны в `ROADMAP_AI.md`.

## Запреты

- Не ставить оценку человеку или дню.
- Не делать алкоголь обязательным центральным экраном.
- Не удалять старые записи и не угадывать значения при backfill.
- Не начинать консолидацию Insight Layer в том же спринте.
