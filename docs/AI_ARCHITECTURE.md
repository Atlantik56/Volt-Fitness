# Эволюционная AI-архитектура VOLT

Статус: целевая архитектура для AI-1…AI-6. Это не требование создать все слои
заново: существующие рабочие модули расширяются и консолидируются.

## Цель

Превратить уже собираемые данные в последовательную историю пользователя при
минимальных расходах API, без переписывания приложения и без передачи сырой
истории внешней модели.

```text
SQLite и доменные данные
        ↓
локальные агрегаты и статистика
        ↓
реестр локальных инсайтов
        ↓
Coach Memory: новизна и повторный показ
        ↓
существующие CoachDecision / progression decisions
        ↓
Lite-текст или компактный JSON для LLM
        ↓
UI: Сегодня / Вечерний прогресс / Моя история / Coach
```

## Существующие части, которые сохраняются

- `lib/coach.ts` — детерминированные решения дня и safety-приоритеты.
- `lib/progression-engine.ts` — подтверждаемая прогрессия нагрузки.
- `lib/coach-insights.ts`, `lib/evening.ts`, `lib/mood.ts` — существующие
  анализаторы, которые нужно подключить к общему контракту, а не переписать.
- `lib/ai-context.ts` — действующий Context Builder.
- `lib/ai-hub.ts` и `lib/ai-coach.ts` — провайдеры и языковой слой.
- `app/progress-model.ts`, `app/training-analytics-model.ts`,
  `lib/coach-weekly.ts` — локальные агрегаты.

## Целевые обязанности

### Статистические примитивы

`lib/stats.ts` предоставляет единое поведение `avg`, `round1`,
`daysBetween` и других действительно общих чистых функций. Пустой ввод не
должен неявно давать `NaN`.

### Context Builder

Один серверный загрузчик данных и один нормализатор создают одинаковый контекст
для chat, MCP и отчётов. LLM-представление — отдельная компактная проекция
контекста, не сам Context.

### Insight Layer

Общий реестр запускает доменные анализаторы и приводит их результаты к одному
контракту. Он не заменяет `CoachDecision` и progression. Общие примитивы
сравнения бакетов и honesty gates допустимы, универсальная бизнес-логика для
всех доменов — нет.

### Coach Memory

Memory хранит факты показа и реакцию пользователя, но не скрытые рассуждения
модели. `evidence_hash` определяет, изменилось ли основание инсайта настолько,
чтобы показать обновление.

### Narrative и Milestones

Milestones строятся детерминированно из тренировок, измерений, рекордов,
фотографий и этапов программы. LLM может сформулировать итог периода, но
события и числа поступают готовыми.

## Потоки

### Ежедневный

1. UI читает известные данные текущего дня.
2. Вечерний чек-ин спрашивает только недостающее.
3. Сервер валидирует и атомарно сохраняет исходные значения.
4. Локальные анализаторы пересчитываются.
5. Memory фильтрует повторы.
6. UI показывает Lite-формулировку без API.
7. LLM вызывается только явным действием или настроенным отчётом.

### Периодический

1. Локальный код строит агрегаты недели/месяца.
2. Анализаторы формируют инсайты с evidence и confidence.
3. Memory выделяет новые и изменившиеся выводы.
4. По запросу пользователя LLM получает компактный JSON и пишет связный итог.

## Границы

- `CoachDecision` не объединяется с Insight Layer: решение дня и наблюдение
  периода имеют разные задачи.
- Прогрессия нагрузки сохраняет собственные safety-инварианты.
- Фотографии не передаются LLM автоматически; допустим факт и дата фото.
- Текст заметок используется локально и передаётся модели только в явно
  обозначенном сценарии с согласием пользователя.
- Причинные модели, диагнозы, фоновые embeddings и vector database не входят в
  AI-1…AI-6.

## Точки расширения

Будущие Garmin, часы и другие источники должны нормализоваться до внутренних
моделей и иметь `source`, а не создавать параллельный путь прямо в LLM.
Биомаркеры добавляются как отдельный доменный анализатор общего контракта.

## Архитектурный критерий успеха

После AI-6 новую категорию данных можно подключить через нормализацию,
доменный анализатор и реестр, не меняя провайдеры LLM и не создавая отдельный
Coach для каждого экрана.
