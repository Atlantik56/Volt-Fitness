## Общий пользовательский сценарий

VOLT показывает план → создаёт черновик → пользователь тренируется без
постоянного ввода данных в телефон → Garmin/FIT подтверждает факт и общие
метрики тренировки → пользователь подтверждает план или меняет только
отклонения → VOLT сохраняет фактическую тренировку и запускает существующую
прогрессию.

Garmin не является обязательным: быстрый сценарий подтверждения должен
работать и без FIT-файла.

# AI-7 — Active Workout 2.0 и черновик по плану

```text
Работаем в проекте VOLT Fitness.

Цель спринта: изменить блок активной тренировки так, чтобы VOLT заранее готовил тренировку по текущему плану, а пользователь мог заниматься без постоянного ввода каждого подхода в телефон.

Перед изменениями:
1. Проверь актуальный main, git status, архитектуру тренировок, workout_logs, strength_logs, progression_decisions и текущий UI запуска тренировки.
2. Найди существующую логику выбора сегодняшней тренировки и сохранения результата.
3. Не дублируй существующие сущности и не переписывай рабочую архитектуру без необходимости.

Нужно реализовать:

1. Состояния блока тренировки:
- запланирована;
- активна;
- ожидает подтверждения результатов;
- завершена.

2. При нажатии «Начать тренировку»:
- создать черновик активной тренировки;
- зафиксировать снимок программы на момент старта;
- сохранить список упражнений, порядок, рекомендуемый вес, подходы и диапазоны повторений;
- не создавать completed workout до фактического завершения;
- повторное нажатие не должно создавать дубль.

3. Экран активной тренировки:
- показать название тренировки;
- список упражнений;
- плановые веса, подходы и повторения;
- время начала;
- кнопку «Завершить тренировку»;
- возможность отменить черновик с подтверждением;
- не требовать вводить каждый подход во время занятия.

4. После завершения:
- перевести черновик в состояние «Ожидает подтверждения»;
- не считать плановые значения автоматически выполненными;
- открыть экран быстрого подтверждения результатов.

5. После перезагрузки страницы активная тренировка должна восстанавливаться.

6. Если программа изменена после старта, активная тренировка должна продолжать использовать сохранённый снимок, а не новый вариант программы.

UX:
- до старта: «Начать тренировку»;
- во время: «Тренировка идёт»;
- после завершения: «Подтвердить результаты»;
- после сохранения: «Тренировка выполнена»;
- отдельная вторичная кнопка «Повторить тренировку», если тренировка уже завершена.

Не делать в этом спринте:
- Garmin;
- FIT-импорт;
- Strava и TrainingPeaks;
- автоматическое распознавание упражнений;
- новые AI-анализаторы;
- изменение CoachDecision и progression-engine, кроме необходимой совместимости.

Тесты:
- создание черновика;
- идемпотентный повторный старт;
- восстановление после перезагрузки;
- снимок программы не меняется после редактирования плана;
- отмена черновика;
- переход active → awaiting_confirmation;
- completed создаётся только после подтверждения;
- отсутствие дублей workout_logs и strength_logs;
- корректная работа неизвестных упражнений.

QA:
- desktop и mobile;
- старт, перезагрузка, завершение, отмена;
- две тренировки подряд;
- уже завершённая тренировка;
- отсутствие горизонтального скролла и ошибок консоли.

В конце:
- запусти tests, typecheck, lint, build и git diff --check;
- не деплой без отдельной команды;
- дай отчёт по архитектуре, изменениям, тестам, рискам и миграциям;
- остановись после завершения этого спринта.
```

# AI-8 — импорт Garmin/FIT как подтверждение тренировки

```text
Продолжаем проект VOLT Fitness после спринта активной тренировки.

Цель спринта: добавить безопасный импорт файла тренировки Garmin в формате FIT, чтобы VOLT получал объективные данные о факте тренировки, длительности, пульсе и калориях.

Важно: в этом спринте не нужна прямая интеграция с Garmin API. Сначала реализовать надёжный provider-independent импорт FIT через ручную загрузку файла. Архитектура должна позволять позже подключить автоматический источник без переписывания логики.

Перед изменениями:
1. Проверь актуальный main и результаты прошлого спринта.
2. Изучи текущие поля workout_logs и details JSON.
3. Проверь, есть ли уже импорт тренировок или обработка FIT.
4. Выбери поддерживаемую библиотеку FIT-парсинга и зафиксируй причину выбора.
5. Не доверяй имени файла и пользовательским метаданным.

Нужно реализовать:

1. Серверный FIT-import pipeline:
- загрузка только допустимого файла;
- ограничение размера;
- безопасный парсинг;
- обработка повреждённых и неподдерживаемых файлов;
- отсутствие исполнения содержимого файла;
- временный файл удаляется после обработки.

2. Из FIT извлекать, когда данные доступны:
- дату и время начала;
- длительность;
- тип активности;
- средний и максимальный пульс;
- калории;
- training effect или аналогичные безопасные метрики, если библиотека их уверенно отдаёт;
- источник: Garmin/FIT;
- внешний идентификатор или устойчивый fingerprint для защиты от дублей.

3. Не импортировать автоматически:
- названия силовых упражнений как достоверный факт;
- рабочие веса;
- повторения и подходы, если структура FIT неоднозначна;
- GPS для силовой тренировки;
- неизвестные поля без документированного назначения.

4. Связь с активной тренировкой:
- после загрузки предложить связать FIT с черновиком в состоянии awaiting_confirmation;
- автоматически предлагать совпадение только по безопасным признакам: дата, время, длительность и тип;
- пользователь должен видеть, почему файл считается совпадающим;
- при сомнительном совпадении выбор только вручную.

5. Если активного черновика нет:
- разрешить создать импортированную общую тренировку;
- либо оставить файл как неподтверждённый импорт;
- не приписывать ему упражнения из программы автоматически.

6. Защита от дублей:
- повторный импорт того же FIT не создаёт новую тренировку;
- вернуть понятное сообщение и ссылку на уже импортированную запись.

7. UI:
- «Загрузить тренировку Garmin»;
- состояние загрузки;
- краткое резюме данных;
- предложение связать с активной тренировкой;
- предупреждение, что Garmin подтверждает факт и физиологические данные, но не все силовые результаты.

Не делать:
- OAuth Garmin;
- автоматическую синхронизацию;
- TrainingPeaks/Strava;
- распознавание каждого упражнения;
- автоматическое заполнение весов и повторений;
- AI-анализ импортированного файла;
- изменение логики прогрессии.

Тесты:
- валидный FIT;
- повреждённый FIT;
- слишком большой файл;
- неподдерживаемая активность;
- повторный импорт;
- fingerprint/idempotency;
- отсутствующие пульс или калории;
- связь с правильным черновиком;
- неоднозначное совпадение;
- файл без активного черновика;
- отсутствие утечки raw FIT в AI-контекст.

QA:
- ручная загрузка на desktop/mobile;
- понятные ошибки;
- повторная загрузка;
- связь с awaiting_confirmation;
- отсутствие ошибок в логах и консоли.

В конце:
- tests, typecheck, lint, build, git diff --check;
- не деплой;
- отчёт: библиотека FIT, модель данных, защита от дублей, ограничения и дальнейшая точка подключения автоматического источника;
- остановись после завершения этого спринта.
```

# AI-9 — быстрое подтверждение и режим «Только изменения»

```text
Продолжаем VOLT Fitness после реализации активной тренировки и FIT-импорта.

Цель спринта: после тренировки пользователь не должен заново вводить каждый подход. VOLT уже знает план и прошлые результаты, Garmin подтверждает факт тренировки, а пользователь подтверждает только то, что изменилось.

Перед изменениями:
1. Проверь актуальный main и обе предыдущие реализации.
2. Изучи сохранение strength_logs, прогрессию, PR, completed/effort/painAfter.
3. Не создавай второй механизм прогрессии и не дублируй парсеры диапазонов повторений.

Нужно реализовать:

1. Экран подтверждения результатов:
для каждого упражнения показать:
- план на сегодня;
- результат прошлого выполнения;
- рекомендуемый вес;
- ожидаемые подходы и повторения;
- статус: «как планировалось», «изменено», «пропущено».

2. Быстрые действия:
- «Всё выполнено по плану»;
- «Всё как в прошлый раз»;
- «Изменить только это упражнение»;
- «Упражнение пропущено»;
- «Добавить внеплановое упражнение».

3. Режим «Только изменения»:
- по умолчанию не показывать большую форму для каждого подхода;
- пользователь выбирает упражнение только при отклонении;
- для изменённого упражнения открыть компактный редактор веса, повторений и подходов;
- поддержать быстрый формат вроде 45×8, 45×8, 45×7;
- корректно работать с собственным весом, временем, дистанцией и неизвестными упражнениями.

4. Важная честность данных:
- кнопка «Всё выполнено по плану» является явным подтверждением пользователя;
- до подтверждения значения остаются плановыми, а не фактическими;
- Garmin сам по себе не подтверждает рабочие веса и повторения;
- сохранить происхождение результата: confirmed_as_planned, manually_edited, skipped, imported_metric.

5. Завершение:
- после подтверждения создать/обновить workout_log;
- построить strength_logs;
- сохранить Garmin-метрики;
- сохранить effort и painAfter;
- запустить существующую прогрессию;
- создать PR и Milestones через существующие механизмы;
- не создавать дубли при повторном сохранении.

6. Частичное выполнение:
- разрешить завершить тренировку, если выполнены не все упражнения;
- Coach и аналитика должны видеть фактическое выполнение;
- пропущенное упражнение не считать выполненным и не использовать для ложной прогрессии.

7. Экран после сохранения:
- длительность и данные Garmin;
- выполненные/пропущенные упражнения;
- изменения относительно прошлого раза;
- PR или вехи;
- статус «Тренировка выполнена»;
- вторичная кнопка «Редактировать результаты».

8. Данные без FIT:
- весь быстрый сценарий должен работать и без Garmin;
- пользователь может завершить тренировку вручную;
- архитектура не должна делать FIT обязательным.

Не делать:
- полное распознавание упражнений Garmin;
- генерацию программы через LLM;
- автоматическое предположение, что план выполнен без нажатия пользователя;
- новую систему progression engine;
- прямую синхронизацию Garmin API;
- кросс-доменные анализаторы.

Тесты:
- «всё по плану»;
- «как в прошлый раз»;
- изменение одного упражнения;
- пропуск упражнения;
- добавление внепланового;
- частичное выполнение;
- повторное сохранение без дублей;
- сохранение Garmin-метрик;
- работа без FIT;
- сохранение effort/painAfter;
- корректное построение strength_logs;
- PR и Milestones;
- отсутствие прогрессии по пропущенному упражнению;
- редактирование уже подтверждённой тренировки.

QA:
- полный путь: VOLT показывает план → старт → завершение → FIT → подтверждение → сохранение;
- тот же путь без FIT;
- desktop/mobile;
- минимальное число действий;
- проверка больших программ и длинных названий;
- отсутствие ошибок консоли и горизонтального скролла.

Критерий UX:
обычная тренировка без изменений должна подтверждаться максимум за 2–3 действия после её завершения.

В конце:
- полный набор tests, typecheck, lint, build, git diff --check;
- не деплой;
- отчёт с количеством действий в основном сценарии, изменениями схемы, тестами, рисками и списком осознанно отложенного;
- остановись после завершения этого спринта.
```

## Осознанно отложено

Прямая автоматическая синхронизация Garmin должна быть отдельным последующим
интеграционным спринтом. AI-8 создаёт provider-independent слой импорта, чтобы
замена ручной загрузки FIT на внешний источник не требовала переписывать
основную логику тренировки.
