# Sprint AI-2 — единый Context Builder

Статус: техническое задание. Начинать только после завершения AI-1.

## Цель

Chat, MCP и будущие отчёты должны видеть одну и ту же нормализованную версию
пользовательских данных. Контекст для локальных вычислений отделяется от
компактной проекции, отправляемой LLM.

## Подтверждённые проблемы

- `wellness_logs.note` сохраняется, но Coach её не видит.
- `mcp-server.ts` передаёт более узкий набор данных, чем chat route.
- Этап программы определяется двумя источниками:
  `app/personal-data.ts` и `program_stages`.
- Новые потребители могут снова скопировать собственную SQL-выборку.

## Ожидаемые точки изменения

- `lib/ai-context.ts`
- новый серверный загрузчик, предпочтительно `lib/ai-context-data.ts`
- `app/api/coach-chat/route.ts`
- `mcp-server.ts`
- при фактическом использовании: `lib/coach-weekly.ts` и route отчёта
- `lib/db.ts` только если без миграции невозможно; по умолчанию миграция не нужна
- тесты `tests/ai-context.test.ts` и/или новые тесты загрузчика

Пути — ориентир после аудита кода, а не требование изменить каждый файл.

## Контракт

Разделить три представления:

1. `AiCoachContextData` — строки/агрегаты, прочитанные с сервера.
2. `AiCoachContext` — нормализованный локальный объект без UI-зависимостей.
3. `renderAiCoachContextText` или JSON-проекция — минимальный payload для LLM.

Контекст должен уметь представить:

- профиль и цели;
- актуальный этап программы;
- измерения и тренды веса;
- тренировки и прогрессию;
- питание;
- активность, шаги, воду и сон;
- вечерние данные;
- настроение и заметки настроения;
- самочувствие, боль, область боли и `wellness_logs.note`;
- личные рекорды;
- факт/дату последнего фото, но не файл;
- позднее — Milestones и отфильтрованные Memory-инсайты.

Это не означает отправку всех перечисленных сырых данных LLM. Нормализованный
локальный контекст может быть богаче облачной проекции.

## Порядок реализации

1. Инвентаризировать фактические SQL-выборки chat и MCP.
2. Зафиксировать единый тип входных данных.
3. Создать один серверный `loadAiCoachContextData(db, options)`.
4. Перевести chat и MCP на этот загрузчик.
5. Добавить `wellness_logs.note` в локальный контекст.
6. Определить приоритет этапа программы:
   фактический `program_stages` для дат с записью; статичный план — fallback.
   Если текущее поведение требует другого выбора, остановиться и
   аргументировать его до изменения.
7. Сделать проекции по назначению: ежедневная, недельная, MCP snapshot.
8. Ограничить объём и исключить секреты/файлы.

## Требования к данным

- Отсутствие строки остаётся `null`, а не превращается в ноль.
- Массивы имеют явное окно периода и стабильную сортировку.
- Время и даты нормализуются в одной временной зоне проекта.
- Заметка самочувствия экранируется как пользовательский текст и никогда не
  становится системной инструкцией для модели.
- Полная `coach_conversation` не смешивается с fitness context.
- API-ключи и значения `settings` не входят в Context.

## Требования к LLM-проекции

- Использовать агрегаты и последние релевантные факты.
- Не отправлять фото, полную историю дневников и все тренировки.
- Явно маркировать пользовательские заметки как данные, не инструкции.
- Добавить измеримый лимит: unit-тест на максимальное число записей/символов
  для типового заполненного fixture.
- Одинаковые входные данные дают одинаковую проекцию.

## Не входит

- Новые инсайты и рекомендации.
- Memory, embeddings, vector database.
- Изменение AI Hub и провайдеров.
- Новый экран Context.
- Массовая перепись routes и SQL вне AI-потребителей.

## Тесты

- Загрузчик возвращает одинаковую полноту для chat и MCP.
- `wellness_logs.note` присутствует в контексте и безопасно размечена.
- Нет данных и реальный ноль различаются.
- `program_stages` и fallback статичного плана проверены отдельными сценариями.
- Порядок исторических записей детерминирован.
- Секреты, фото-binary/path и лишняя полная история не попадают в LLM payload.
- Старые тесты AI Hub, Coach и MCP проходят.

## Критерии готовности

- У chat и MCP нет параллельных ручных наборов входных полей.
- Новый потребитель может получить Context одним публичным вызовом.
- Контекст не стал дороже за счёт неконтролируемой сырой истории.
- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build` проходят.
- В `ROADMAP_AI.md` записаны фактические файлы, решение по этапам программы и
  результат проверки.
