# Sprint AI-6 — Milestones и история пользователя

Статус: продуктовое и техническое задание. Начинать после AI-5 и вместе с
ограниченным набором кросс-доменных инсайтов.

## Цель

«Моя история» должна отвечать на вопрос «как менялась моя жизнь?», а не только
показывать набор графиков. Детерминированный агрегатор строит вехи из уже
существующих фактов; пользователь может добавлять личные вехи вручную.

## Источники

- `measurements`
- `workout_logs`
- `strength_logs` и подтверждённые личные рекорды
- `program_stages`
- `photos` — только факт и дата
- `mood_logs`
- `daily_activity`
- существующая аналитика периодов

Перед реализацией сверить реальные схемы и не делать вторую копию исходных
данных в milestone.

## Типы автоматических вех

Первый ограниченный набор:

- первая тренировка после старта истории;
- 10/25/50/100 завершённых тренировок;
- новый подтверждённый личный рекорд;
- новый минимальный вес относительно предыдущих замеров;
- завершение этапа программы;
- лучший завершённый месяц по регулярности при достаточных данных;
- контрольное фото спустя заданный период;
- устойчивое улучшение показателя только при honesty gate.

Не использовать серии «дней без пива», отрицательные анти-достижения,
штрафные вехи и сравнение с другими людьми.

## Контракт

```ts
type Milestone = {
  id: string;
  kind: string;
  occurredAt: string;
  title: string;
  summary: string;
  sourceIds: string[];
  sourceRevision: string;
  automatic: boolean;
};
```

Автоматический id должен быть стабильным и идемпотентным. Пересчёт одной
истории не создаёт повторов.

## Хранение

Сначала реализовать автоматический агрегатор без новой таблицы, если веху можно
полностью воспроизвести из источников. Новая таблица `milestones` допустима
только для:

- ручных вех;
- пользовательского текста;
- явного скрытия/закрепления;
- событий, которые невозможно восстановить.

Не копировать в таблицу вес, тренировку или фото целиком. Хранить ссылки на
источники и минимальный snapshot только при доказанной необходимости.

## UX «Моей истории»

- Основной вид — компактная временная шкала.
- Группировка по месяцам/годам.
- По умолчанию ограниченное число последних вех.
- «Показать ещё» или фильтр по категории вместо бесконечного списка.
- Текст заметок раскрывается по клику.
- Фильтры: тело, тренировки, состояние, этапы, личные вехи.
- Главная страница показывает максимум одну актуальную ссылку/веху, не всю
  ленту.
- Фото остаются приватными и не раскрываются автоматически.

## Месячный обзор

Локальный код готовит:

- начало/конец периода;
- изменение веса при достаточных замерах;
- число тренировок и регулярность;
- личные рекорды;
- важные этапы;
- ограниченные подтверждённые кросс-доменные инсайты;
- недостаток данных.

Lite Coach собирает шаблонный итог без API. По явной кнопке «Объяснить месяц»
LLM получает компактный JSON и пишет связный текст без новых фактов.

## Ручные вехи

Пользователь может добавить:

- дату;
- короткий заголовок;
- необязательную заметку;
- категорию.

Редактирование и удаление требуют подтверждения. Ручной текст не используется
как доказательство автоматического инсайта и не отправляется LLM без явного
действия.

## Ожидаемые точки изменения

- новый локальный агрегатор `lib/milestones.ts`
- «Моя история» в `app/page.tsx` или выделенный компонент
- при необходимости аддитивная миграция в `lib/db.ts`
- API/service для ручных вех
- `lib/ai-context.ts` — только компактная проекция выбранных вех
- новые unit-, service- и UI tests

## Не входит

- Социальная лента и сравнение пользователей.
- Автоматическая психологическая интерпретация жизни.
- Видео/визуальное распознавание фото.
- Генерация фактов LLM.
- Push-кампании и gamification Sprint 8.
- Перестройка всех экранов «Моей истории».

## Тесты

- Стабильные id и отсутствие дублей после повторного пересчёта.
- Границы 9/10, 24/25, 49/50 тренировок.
- Личный рекорд только при реальном превышении.
- Новый минимум веса с несортированными и частичными замерами.
- Завершение/пересечение program stage.
- Месяц с недостатком данных не объявляется «лучшим».
- Удаление/редактирование источника корректно меняет автоматическую веху.
- Ручные вехи CRUD и подтверждение удаления.
- Группировка/фильтры не теряют события.
- LLM payload не содержит фото и необязательный полный текст заметок.
- Desktop/mobile QA длинной истории.

## Критерии готовности

- «Моя история» показывает осмысленную, масштабируемую временную шкалу.
- Автоматические вехи воспроизводимы и объяснимы источниками.
- Нет отрицательных или стыдящих достижений.
- Месячный обзор работает в Lite-режиме без токенов.
- LLM не создаёт числа, даты и достижения.
- Полные проверки и ручная QA проходят.
- Реализованные типы вех и исключения записаны в `ROADMAP_AI.md`.

## Запреты

- Не сохранять вычисляемые дубликаты без причины.
- Не считать отсутствие записи негативным событием.
- Не превращать алкоголь в систему streak.
- Не добавлять новые категории за пределами согласованного первого набора.
