# Roadmap AI-спринтов VOLT

Статус: текущий план. Начальная точка: `main` после внедрения «Вечернего
прогресса» и «Моей истории» 28 июля 2026 года.

Этот roadmap заменяет прежнюю спринтовую очередь для AI-развития. Исторические
Sprint 1–8 остаются в `VOLT_ROADMAP.md`, но не должны выполняться параллельно с
AI-1…AI-6 без отдельного решения пользователя.

## Порядок

|---|---|---|---|

| AI-2 | Сделать единый Context Builder | `AI_CONTEXT.md` | следующий |
| AI-3 | Добавить адаптивный вечерний чек-ин | `EVENING_CHECKIN.md` | ожидает AI-2 |

| AI-6 | Кросс-доменные инсайты и Milestones | `INSIGHT_ENGINE.md`, `MILESTONES.md` | ожидает данных и AI-5 |

diff, результаты тестов и нерешённые вопросы. Следующий спринт не начинать без
отдельного указания.

## AI-1 — стабилизация аналитики

### Цель

Убрать подтверждённые расхождения до появления общего Insight Layer и Memory.
Спринт не меняет пользовательский функционал.

### Scope

- Создать `lib/stats.ts`; унифицировать `avg`, `round1`, `daysBetween`.
- Явно определить поведение пустых массивов и некорректных дат.
- Заменить дубли только в подтверждённых потребителях:
  `lib/coach.ts`, `lib/coach-insights.ts`, `lib/coach-weekly.ts`,
  `lib/evening.ts`, `lib/mood.ts`, `lib/progression-engine.ts`,
  `app/progress-model.ts`, `app/exercise-progress.ts`.
- Вынести общий `weightStep`, если обе реализации действительно семантически
  одинаковы; иначе задокументировать отличие.
- Провести инвентаризацию трёх источников подсказок прогрессии:
  `lib/progression-engine.ts`, `app/exercise-progress.ts`,
  `StrengthAdvice` в `app/fitness-features.tsx`.
- Выбрать канонический источник правил и убрать противоречивые советы, не
  объединяя разные UX-моменты искусственно.

### Не входит

- Новый UI, миграции БД, новые инсайты.
- Изменение safety-порогов без отдельного продуктового решения.
- Repo-wide cleanup утилит и типов.
- Переименование существующих движков.

### Критерии готовности

- Общие функции имеют документированный контракт и unit-тесты, включая пустой
  ввод, один элемент, дробные значения и границы дат.
- В затронутых файлах нет локальных копий с тем же смыслом.
- Подсказки прогрессии не противоречат подтверждаемому предложению.
- Существующие snapshots/тексты меняются только при исправлении
  подтверждённого расхождения.
- Полный test/typecheck/lint/build проходит.

### Результат AI-1

Выполнено 28 июля 2026 года. Все критерии готовности выполнены.

**Изменённые файлы:**

- `lib/stats.ts` (новый) — единственное место с `avg`, `round1`, `daysBetween`.
- `tests/stats.test.ts` (новый) — контрактные тесты статистических примитивов.
- `tests/progression-consistency.test.ts` (новый) — согласованность `weightStep`
  и отсутствие противоречий по направлению между live-подсказкой и
  подтверждаемой прогрессией.
- `lib/coach.ts`, `lib/coach-insights.ts`, `lib/coach-weekly.ts` — локальные
  `round1`/`daysBetween`/`avg` заменены на импорт из `lib/stats.ts`.
- `lib/evening.ts` — локальная `avg` заменена на `export { avg } from "./stats.ts"`
  (re-export сохраняет прежний путь импорта для `lib/mood.ts`); четыре места с
  разностью двух `avg()` получили явное `!` (non-null assertion) — они уже были
  защищены проверками `.length >= N` до вызова, поведение не изменилось.
- `lib/mood.ts` — два места с разностью `avg()` получили `!` по той же причине.
- `lib/progression-engine.ts` — локальный `round1` заменён на импорт из
  `lib/stats.ts`; остаётся каноническим источником `weightStep`.
- `app/progress-model.ts` — локальный `round1` (уже нормализовавший `-0`)
  заменён на импорт из `lib/stats.ts`.
- `app/exercise-progress.ts` — локальный `weightStep` удалён, заменён на
  `import … export { weightStep }` из `lib/progression-engine.ts`.
- `app/fitness-features.tsx` (`StrengthAdvice`) — убран третий независимый
  набор правил прогрессии (формула `+1 кг` после одной лёгкой тренировки);
  текст стал нейтральным отображением факта, ссылающимся на решение VOLT
  Coach. Мёртвые `list`/`last` в этой же функции удалены как следствие.

**Контракт статистических примитивов (`lib/stats.ts`):**

- `avg([])` → `null` (не `NaN`). `avg([x])` → `x`.
- `round1(n)` — округление до одного знака, `-0` нормализуется в `0`
  (устраняет реальный баг: без нормализации `coach.ts` мог показать «+-0 кг»
  для малой отрицательной дельты веса).
- `daysBetween(from, to)` — целые сутки между датами `"YYYY-MM-DD"`, всегда
  через `T00:00:00Z`; одинаковые даты → `0`; некорректная дата → `null`, не
  `NaN`. Не зависит от `Date.now()`, локали или текущей таймзоны.

**Подтверждённое расхождение:** `avg([])` в `lib/evening.ts` возвращала `NaN`
(0/0), а в `lib/coach-weekly.ts` — `null`. Устранено переходом на общий
контракт; ни один существующий вызов не полагался на `NaN`-поведение (все
обёрнуты в `.length` проверки или уже ожидали `null`).

**`weightStep`:** реализации в `lib/progression-engine.ts` и
`app/exercise-progress.ts` были побайтово идентичны (одинаковый порог `<=0`,
одинаковый паттерн для гантелей, одинаковые значения 1/2.5 кг). Объединены:
каноническая функция — в `lib/progression-engine.ts`, `app/exercise-progress.ts`
переиспользует её через re-export.

**Три источника подсказок прогрессии:**

1. `lib/progression-engine.ts` (`buildExerciseProgression`) — **канонический**
   источник подтверждаемого изменения нагрузки. Работает после завершения
   тренировки, использует историю прошлых сессий, `painAfter`, `coachAction`,
   `workoutComplete`, `targetMaxReps`. Требует **двух подряд** «Легко»/«Тяжело»
   для increase/decrease; deload — только при тяжёлой боли.
2. `app/exercise-progress.ts` (`progressionDecision`) — live-подсказка
   на следующий подход прямо во время тренировки, использует последнюю
   зафиксированную запись (в т.ч. текущую, ещё не сохранённую). Более
   консервативных подтверждений не ждёт, но и не идёт против направления
   канонического решения — оставлен как самостоятельный UX-момент, как
   разрешено ТЗ («живая подсказка» ≠ «подтверждаемое решение»).
3. `app/fitness-features.tsx` (`StrengthAdvice`) — прежде содержала третий,
   независимый набор правил (числовая формула `+1 кг` без учёта `weightStep`,
   срабатывающая после одной лёгкой тренировки вместо двух). Это было
   единственное подтверждённое противоречие по направлению/числу. Исправлено:
   компонент больше не предлагает конкретное число, только нейтрально
   описывает факт и ссылается на решение VOLT Coach.

Прямого противоречия по направлению (одна сторона — increase, другая —
decrease/deload для одних и тех же сигналов) между источниками 1 и 2 не
обнаружено и зафиксировано тестами `tests/progression-consistency.test.ts`.

**Результаты проверок:** `npm test` — 212/212 passed; `npm run typecheck` —
без ошибок; `npm run lint` — 0 ошибок, 8 предупреждений (все
`react-hooks/exhaustive-deps` и один `no-unused-vars` в `lib/evening.ts:142`
— все предсуществующие, не в затронутых этим спринтом строках); `npm run
build` — успешно.

Коммит не создан и push не выполнен — по прямому указанию пользователя.

## AI-6 — связи и история

### Предусловия

- AI-1…AI-5 завершены.
- По новым полям накоплен минимальный объём реальных данных.
- Порог выборки фиксируется до реализации каждого анализатора.

### Scope

- Ограниченный набор кросс-доменных анализаторов из `INSIGHT_ENGINE.md`.
- Автоматические и ручные Milestones из `MILESTONES.md`.
- Отображение истории в «Моей истории» без перегрузки главного экрана.

### Критерии готовности

- Ни один текст не превращает корреляцию в причинность.
- Каждый вывод показывает/хранит evidence count и confidence.
- Слабые выборки дают честное пустое состояние.
- Milestones идемпотентны и не дублируются после пересчёта.
- LLM получает только готовые агрегаты.
- Полные проверки и ручная desktop/mobile QA проходят.

## Общие запреты

- Не начинать следующий спринт автоматически.
- Не пушить и не деплоить без разрешения пользователя.
- Не менять приложение вне scope текущего спринта.
- Не удалять пользовательские данные и старые миграции.
- Не использовать LLM для вычислений, confidence или выбора фактов.
- Не превращать заметки пользователя в диагнозы.
